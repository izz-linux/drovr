# Cleanup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Archive plans older than `reports.archive_after_days` into `<plans>/archive/`, prune resolved Inbox items older than `inbox.keep_days`, daily and on demand.

**Architecture:** A new core module, `cleanup.rs`, does the work and can also only plan it (dry run). The store gets an Inbox prune and a report path move. The plan, report and record listings skip `archive/`. The app's background loop runs it once a day, Settings has a button, and the CLI has `drovr cleanup [--dry-run]`.

**Tech Stack:** Rust (`drovr-core`, `drovr-cli`, Tauri `drovr-app`), Svelte 5 for the button, pnpm.

**Spec:** `docs/superpowers/specs/2026-11-18-cleanup-design.md`

## Global Constraints

- **Config:** `reports.archive_after_days: u32` and `inbox.keep_days: u32` in a new `[inbox]` section. Both default to `0`, which means off.
- **Archive folder:** `<reports.dir>/archive/`, holding top-level entries moved whole. A collision gets `-2`, `-3` and so on, before the extension for files.
- **Never archived:** `archive`, `retros`, names starting with `.`, and a folder whose name equals a group in `store.groups()`.
- **Age:** the newest mtime of any file under the entry, searched recursively. A loose file uses its own mtime. It's old when that is older than `now - days*86400`.
- **Inbox:** delete where `status != 'pending' AND COALESCE(answered_ts, ts) < cutoff AND NOT (status IN ('answered','rejected') AND delivered = 0)`.
- **Daily gate:** `<home>/cleanup.json`, `{"last_run": <unix secs>}`. Due when it's missing or more than 86,400 seconds old.
- **Copy:** the Settings toast reads "Archived N plans and removed M Inbox items." The CLI prints one line per moved entry (`archived <name> → archive/<name>`) and a summary line. `--dry-run` prefixes lines with `would`.
- No new dependencies. Commits are single-line Conventional Commits with no trailers. Run fmt, tests, clippy and `pnpm check` as separate commands. pnpm only.
- README.md, USAGE.md and config.example.toml are updated in this PR.

## Review Focus

1. **A long-running ticket** whose folder is old but contains one fresh file stays put. (Task 1 test.)
2. **An active group's folder** is never moved, whatever its age. (Task 1 test.)
3. **An answer an agent hasn't received yet** is never deleted, whatever its age. (Task 1 test.)
4. **Dry run** changes nothing on disk or in the database. (Task 1 test, and the CLI flag in Task 2.)
5. **After archiving,** Reports, the plans folders and ticket timelines don't show archived items, and nothing errors on the moved files. (Task 1 tests.)

- [ ] **Step 1: Write the failing tests** in `cleanup.rs`. Use a temp plans dir, `filetime`-free mtimes by passing `now` far in the future rather than touching mtimes (e.g. files written now, `now = real_now + 40 days`), and a temp `Store`.
  - `archives_old_entries_whole`:
    - `old-group/SRE-1/ledger.jsonl` and `loose.html`, both 40 days old relative to `now`, with `archive_after_days = 30`
    - both move to `archive/old-group/SRE-1/ledger.jsonl` and `archive/loose.html`
    - `Outcome.archived` lists them
  - `keeps_folders_with_a_fresh_file`:
    - `busy/` has an old file plus a file whose mtime is within the window
    - to make one file "fresh" under a future `now`, write it and then set `now` so that only that file is inside the window. The simplest way is to create `busy` with two files and use a `now` where `days = 30` puts the cutoff between them. If you can't control mtimes portably, use `std::fs::File::set_modified` (std, Rust ≥ 1.75).
    - it stays
  - `never_archives_reserved_or_active`: `archive/`, `retros/`, `.hidden/` and a folder named after a group added via `store.add_group("live", …)` all stay.
  - `collision_gets_a_suffix`: `archive/x/` exists, and archiving `x/` lands at `archive/x-2/`. A file `a.html` with an existing `archive/a.html` lands at `archive/a-2.html`.
  - `report_meta_follows_the_move`: a `report_meta` row for `<plans>/old/r.html` ends up at `<plans>/archive/old/r.html`.
  - `dry_run_changes_nothing`: the same setup as the first test with `dry = true` returns the same `Outcome`, and every file is still in place. The Inbox count is reported but nothing is deleted.
  - `zero_days_is_off`: both settings at 0 means an empty `Outcome` and nothing moved.
  - `prunes_resolved_inbox_items`:
    - add items, then set their status and `answered_ts` via store methods or SQL in the test
    - an old dismissed item and an old answered-and-delivered item are deleted
    - an old pending item, an old answered item with `delivered = 0`, and a recent dismissed item stay
  - `daily_gate`: `due` is true without a file, false right after `mark_ran(now)` at `now + 3600`, and true at `now + 90000`.
  - In `reports.rs` and `ledger.rs` tests (or `cleanup.rs` via their public fns): after archiving, `reports::list`, `reports::folders` and `ledger::list` don't include anything under `archive/`.
