# PRs View Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move PR review offers out of the Inbox into a PRs view (⌘8) that tracks each PR from offer to merge: New (Dispatch/Dismiss), then Reviewing, then gone on merge or dismiss. Notifications and badges come with it. Settings moves to ⌘,.

**Architecture:**
- A `review_prs` table in the store holds each PR's lifecycle and live GitHub state.
- `pr_review` writes rows instead of Inbox items, and refreshes open rows each poll.
- Engine `dispatch_pr`/`dismiss_pr` drive the transitions.
- The app adds the rows to `Snapshot`, a `Prs.svelte` view, notifications and the keyboard change.

**Tech Stack:** Rust (`drovr-core`, `drovr-cli`, Tauri `drovr-app`), Svelte 5, pnpm.

**Spec:** `docs/superpowers/specs/2026-11-19-prs-view-design.md`

## Global Constraints

- **Statuses:** exactly `new`, `dispatched`, `dismissed` and `closed`. Only `new` and `dispatched` are "open".
- **Row key:** the lowercased canonical URL `https://github.com/<owner>/<repo>/pull/<n>`, the same normalization `pr_review` uses for `seen`.
- **Inbox:** the poll no longer creates `review` Inbox items. Migration moves pending ones into rows as `new` and resolves the items `answered` with "Moved to PRs".
- **Removing a reviewer** always goes through the existing `Engine::remove`, which force-cleans `pr-reviewer` worktrees.
- **Copy:**
  - group headings: "New" and "Reviewing"
  - buttons: **Dispatch reviewer**, **Dismiss**, **Open on GitHub**, **Open reviewer**, **Report**, **Refresh**
  - notification: one row → title "PR to review", body "owner/repo#n: title"; several → title "N PRs to review", with one line per PR
  - empty state: "No PRs waiting on you."
- **Keyboard:**
  - ⌘8 is PRs, and Settings is ⌘, (keydown, plus a **Settings…** item in the drovr app menu with accelerator `CmdOrCtrl+,`, emitting `menu:menu-settings`)
  - the PRs nav item shows when `cfg.review.slack_channels` or `cfg.review.github_teams` is non-empty, or any open rows exist. Expose a `review_enabled` bool in `defaults()` or wherever the app reads config flags; check how `workflow` reaches `app.defaults`.
- No new dependencies. Commits are single-line Conventional Commits with no trailers. Run fmt, tests, clippy and `pnpm check` as separate commands. pnpm only. README and USAGE are updated in this PR (Task 2).

## Review Focus

1. **No Inbox items for PRs any more,** and the migration moves pending ones exactly once. (Task 1 test.)
2. **Dismiss on a Reviewing row** removes the reviewer, worktree included, and hides the row; a later poll doesn't re-offer it. (Task 1 test.)
3. **Merge/close cleanup** follows `remove_when_closed`. (Task 1 test.)
4. **One `gh pr view` per open row per poll,** with nothing extra.
5. **Keyboard:** ⌘1–⌘7 and ⌘9 are unchanged, ⌘8 is PRs, ⌘, is Settings, and the menu item works.

### Task 1: Core: rows, lifecycle and the CLI

**Files:**
- Modify: `crates/drovr-core/src/store.rs`
  - the `review_prs` table in the schema (around :14-80) and a migration step (see the `ALTER TABLE` pattern around :272-308) that also moves pending `review` items
  - `pub struct ReviewPr` (Serialize, Clone, Debug), with all the columns
  - methods: `upsert_review_pr(&ReviewPr)` (on conflict, keep the existing `status`, `agent`, `offered_ts` and `decided_ts`; update the descriptive fields); `review_prs(open_only: bool)`; `review_pr(key)`; `set_review_pr_status(key, status, agent: Option<&str>)`; `update_review_pr_live(key, pr_state, draft, ci, review_decision, my_review)`; `prune_review_prs(before)`
- Modify: `crates/drovr-core/src/pr_review.rs`
  - `offer()` writes a row. With `auto_dispatch`, dispatch, then write it as `dispatched` with the agent. On dispatch failure, write it as `new`. Keep the `-> bool` contract for `seen`.
  - Add `refresh_open(engine, login)`, run at the end of each due `poll_at`, before `remove_closed`:
    - for each open row: `gh pr view <url> --json state,isDraft,statusCheckRollup,reviewDecision,latestReviews`
    - map CI the way `watch.rs` does; check for a helper you can reuse
    - `my_review` = the state of the latest review whose `author.login` equals the login (case-insensitive), else ""
    - MERGED or CLOSED: status `closed`; if dispatched and `remove_when_closed`, run `engine.remove(agent)`
    - errors per row: log and continue
  - `remove_closed` only handles reviewers with no row.
  - Prune `dismissed`/`closed` rows older than 90 days whenever the poll saves.
- Modify: `crates/drovr-core/src/engine.rs`
  - `pub fn dispatch_pr(&self, key: &str) -> Result<Agent>`: the row must be `new`; call `dispatch_review(url)`, then set `dispatched` plus the agent; on Err the row stays `new`
  - `pub fn dismiss_pr(&self, key: &str) -> Result<()>`: if an agent is set and exists, `remove` it; set `dismissed`
  - `dispatch_review`'s CLI path: `drovr review <url>` upserts the row and marks it `dispatched`. Put that in a small `Engine::review_url(url)` wrapper the CLI calls, so `dispatch_review` itself stays as it is.
- Modify: `crates/drovr-cli/src/main.rs`
  - `review_args` accepts `list` and `dismiss <url>`
  - `list` prints `new|reviewing  owner/repo#n  title  (source)  agent`, or "No PRs waiting on you."
  - `dismiss` normalizes the URL to a key and calls `dismiss_pr`
  - the USAGE string is updated

**Interfaces:**
- Produces: `store::ReviewPr`, `Store::{review_prs, set_review_pr_status, …}`, `Engine::{dispatch_pr, dismiss_pr, review_url}`, and `pr_review::poll` (signature unchanged).
